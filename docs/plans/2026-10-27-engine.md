# «Сеть насквозь», plan 1: the engine

> Changed (27.10, coordinator): the course's title in the UI is «Сквозь время» (Martin's name); `app.title` and the tests that read it say so. The repository stays `learn` at `/learn`. The favicon is the mascot's `design/mascot/echo-mark.svg`, and Task 11's `Guide.svelte` renders `design/mascot/echo.svg` (its README is the class contract).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static SvelteKit app at `/learn` that renders validated lessons from a concept graph, keeps all progress in the browser (export and import included), runs tests, spaced repetition, sandboxed practice with checks, a scripted guide with an optional own-key model, and gamification. It ships with two reference lessons and a green CI, published to GitHub Pages.

**Architecture:**
- Pure logic lives in framework-free TypeScript modules under `src/lib/*`, each with unit tests: schema, graph, store, SRS, grading, the checks DSL, guide, game.
- Svelte 5 components render them.
- Content is mdsvex files plus YAML, validated by the same Zod schemas at build time and by a CLI in CI.
- The practice preview is a sandboxed `iframe srcdoc` that runs the checks and posts results back.

**Tech Stack:**
- Node 24 LTS; SvelteKit 3.x (`adapter-static`); Svelte 5 (runes); TypeScript;
- zod 4; mdsvex; yaml; idb 8 (with fake-indexeddb in tests); ts-fsrs 5; CodeMirror 6; @electric-sql/pglite (lazy);
- vitest; @testing-library/svelte; @playwright/test; @axe-core/playwright; @lhci/cli.

**Spec:** `docs/specs/2026-10-27-learn-design.md`. Read it before any task; section numbers below refer to it.

## Global Constraints

- Served at `paths.base = "/learn"`, prerendered, with no server routes (§4.1).
- No network request to a third party before the person asks for it. The preview sandbox has `sandbox="allow-scripts"` and no `allow-same-origin`, and its CSP blocks network access (§4.4).
- All progress is in IndexedDB. The person's own key is never in a URL or a log, and goes only to the provider the person chose (§4.3, §4.5).
- WCAG 2.2 AA, keyboard-first, `prefers-reduced-motion` honoured (§4.7).
- The first route is under 150 KB of JS gzipped. CodeMirror, PGlite and the guide's animation load lazily (§6).
- UI strings come from `src/lib/i18n/ru.json`; no Russian literal in a component (§4.2).
- Practice checks are written against data fields, never against the persona's literal text (§3.2).
- Every file you create is under the Apache-2.0 licence. Every lesson's text is CC BY-SA 4.0.
- Commit after each task with explicit paths (never `git add -A`).

```ts
import ru from './ru.json';
const dict: Record<string, string> = ru;
export function t(key: string, vars: Record<string, string | number> = {}): string {
  const s = dict[key];
  if (s === undefined) throw new Error(`i18n: missing key ${key}`);
  return s.replace(/\{(\w+)\}/g, (_, k) => String(vars[k] ?? `{${k}}`));
}
export function plural(n: number, [one, few, many]: [string, string, string]): string {
  const m10 = n % 10, m100 = n % 100;
  if (m10 === 1 && m100 !== 11) return one;
  if (m10 >= 2 && m10 <= 4 && (m100 < 12 || m100 > 14)) return few;
  return many;
}
```
